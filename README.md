# Mask-Conditioned Risk Switching (MRS) for Impulse Noise Removal

Reference implementation and the complete experimental pipeline for the paper

> **Mask-Conditioned Risk Switching for Impulse Noise Removal**
> Khuwaja Muhammad Momin, Institute of Management Sciences (IMSciences), Peshawar

Every table and every figure in the paper is produced by a script in this repository, from the images in this repository, with fixed seeds. Nothing is copied by hand.

---

## What the method does, in one paragraph

Two-stage impulse filters repair a corrupted pixel and then decide whether to refine that repair. The usual decision compares a noise density with a constant — the filter this work builds on refines only when the whole image is more than 45% corrupted. A density cannot tell a smooth region from a detailed one, although the two need opposite treatment. MRS replaces the constant with a comparison of two **predicted errors**. Because impulse noise leaves the surviving pixels exact, the error of each candidate repair is a pure prediction error over a source set that the noise mask fixes, and it can be written from the image structure function estimated on surviving pixel pairs. No reference image and no tuned constant enter the decision.

```bash
git clone <this repository>
cd MRS-impulse-noise
pip install -r requirements.txt

python3 experiments/mrs_demo.py            # one image, one density, in a few seconds
```

The demo restores a corrupted image with the published rule and with MRS and prints both PSNRs, so you can see the method work before running anything long.

## Reproducing the paper

Run these in order. Each writes JSON into `results/`. The JSON files are **already committed**, so you can check any number in the paper without running anything.

| Script | Time | Produces |
|---|---|---|
| `experiments/h3_metrics.py` | ~15 min | Tables II, III, IV, VIII, XII — the 162-condition sweep, PSNR / SSIM / IEF / residual impulses |
| `experiments/p2_ablation_host2.py` | ~3 min | Tables V and XI — the geometry ablation and the second host |
| `experiments/p2_localD.py` | ~5 min | Table VII — global against local structure function |
| `experiments/p2_host2_exactS2.py` | ~35 min | the Section V-B7 diagnostic |
| `experiments/h1_run.py bsds200` | ~10 min | Table IX, Berkeley half — needs the dataset, see below |
| `experiments/h1_run.py testimages40` | ~25 min | Table IX, TESTIMAGES half |
| `experiments/redraw_figs.py` | ~1 min | Figures 6, 7, 8, 9 |
| `experiments/redraw_fig10.py` | ~1 min | Figure 10 |

Timings are for one core. The scripts save progress as they go, so stopping and restarting is safe.

### The experimental grid

Six images x nine densities from 0.1 to 0.9 x three noise realisations. Below the published 45% cutoff this gives the **72 conditions** the paper reports on: six images at the four densities 0.1 to 0.4, with three realisations each.

Noise is generated by NumPy's **PCG64**, seeded with **1, 2 and 3** for the three realisations. `u` is drawn for the whole image, then `v`. The generator is reseeded before every condition, so every filter sees an identical corrupted input.

### The two large datasets

Table IX uses 200 Berkeley images and the 40 TESTIMAGES base photographs. They are **not** included here — they are not ours to redistribute. Download them yourself:

- **Berkeley (BSDS500):** https://www2.eecs.berkeley.edu/Research/Projects/CS/vision/grouping/BSR/BSR_bsds500.tgz — the 200 images are in `BSR/BSDS500/data/images/train/`. Note that the archive is a plain tar despite the `.tgz` name; use `tar -xf`.
- **TESTIMAGES:** https://sourceforge.net/projects/testimages/files/SAMPLING/8BIT/GRAY/SAMPLING_8BIT_GRAY_1200x1200.tar.bz2 — the 40 base photographs are the files whose path contains `C00C00`; everything else is a shifted copy.

Then convert them into the form the pipeline expects:

```bash
python3 experiments/prepare_datasets.py  BSR/BSDS500/data/images/train  bsds200
python3 experiments/prepare_datasets.py  SAMPLING_8BIT_GRAY_1200x1200   testimages40 --filter C00C00 --limit 40
```

This writes 8-bit greyscale PNG into `data/bsds200/` and `data/testimages40/`, along with a `MANIFEST.txt` in each recording exactly which files were used.

## Layout

```
src/                 the method
  mrs_core.py          the risk of an averaged repair (Eq. 6), the structure function,
                       the two source sets, the two predicted risks
  mrs_run.py           the full pipeline, the local-D variant, the noise generator
  nvbmf.py             the host filter and the metrics: PSNR, SSIM, IEF, residual impulse rate
  baselines.py         the median filter and the adaptive median filter, written from
                       Gonzalez & Woods rather than taken from a toolbox

experiments/         one script per experiment, plus the dataset and figure helpers
matlab/              an independent MATLAB port and its verification harness
images/              the six test images, with sources and licences in images/README.md
results/             the JSON output of every experiment, as used in the paper
figures/             the figures as they appear in the paper
```

### Where the equations live

| Paper | Code |
|---|---|
| Eq. (6), the extension variance | `mrs_core.risk_stage1`, `mrs_core.risk_stage2` |
| Eq. (7), the first source set | `mrs_core.risk_stage1` |
| Eq. (8), the second source set | `mrs_core.risk_stage2` |
| Eq. (9), the structure function from surviving pairs | `mrs_core.structure_function_global` |
| Eq. (10), the switching rule | the `V2 < V1` comparison in `mrs_run.run_one` |

**One detail worth knowing.** The pairwise term of Eq. (6) sums over the *ordered* pairs of the source set, so it includes the terms where both members are the same source. The lag is zero there and `D(0) = 0`. `numpy.interp` clamps below the smallest measured lag, so `Dcurve.__call__` and `LocalD.__call__` both force the value to zero at zero lag. Removing those two lines reproduces an earlier, incorrect behaviour that biases the rule against refining; it changes the headline result from +0.572 dB to +0.483 dB.

## The MATLAB port

`matlab/` contains an independent implementation, written from the equations rather than translated line by line, and it runs in MATLAB R2018b or later and in Octave 6 or later.

```matlab
>> cd matlab
>> setup_paths
>> selfcheck                      % unit checks on every component
>> verify_against_reference       % cross-language check against the Python run
>> mrs_demo                       % the same demo as the Python one
```

`verify_against_reference` loads `matlab/verification/python_reference.mat`, feeds the MATLAB code the *same* corrupted images the Python code saw, and compares the Stage-1 repair, the Stage-2 candidate, both predicted risks, the structure-function curve and five PSNRs. It asserts that the two implementations make identical refine decisions on every repaired pixel.

If you change the Python side, regenerate that file:

```bash
python3 experiments/export_reference.py
```

Two things the port has to get right, and that a naive translation gets wrong:

- **`box_sum.m`** — NumPy indexes from 0, MATLAB from 1. A direct port shifts the 5x5 local-density window by one row and column.
- **`round_half_even.m`** — MATLAB's `round` goes half away from zero, NumPy's goes half to even. Stage-1 repairs are means of small integer sets, so exact halves are common and about 4400 pixels differ on a 512x512 image.

## Requirements

Python 3.8 or later, and:

```
numpy
pillow
matplotlib     # figures only
scipy          # only for experiments/export_reference.py
```

No image-processing library is used for any measured quantity. Every filter and every metric is built from array arithmetic, so no result depends on the internal choices of a toolbox.
